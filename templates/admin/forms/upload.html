JSON wymaga title i listy fields; pola wejściowe muszą mieć unikalne name i obsługiwany type. HTML wymaga kontrolek z name. DOCX obsługuje znaczniki {{ '{{ nazwa_pola }}' }} lub etykiety, np. „Imię: ______”.

JSON

Struktura główna: title, opcjonalne name, description, slug oraz tablica fields. Pole może zawierać name, label, type, required, options, placeholder, help_text, default, validation, width, visible_if, readonly i stage.

Obsługiwane typy: text, textarea, email, tel, number, date, select, radio, checkbox, pesel, section, static_text i training_selection.

{
  "title": "Formularz zgłoszeniowy",
  "fields": [
    {"type": "text", "name": "imie", "label": "Imię"},
    {"type": "email", "name": "email", "label": "E-mail", "required": false}
  ]
}

HTML i DOCX

W HTML użyj input, select lub textarea z unikalnym atrybutem name. W DOCX użyj znaczników {{ '{{ nazwa_pola }}' }} albo etykiet zakończonych dwukropkiem i miejscem do wpisania.

Zmienne systemowe

Identyfikatory techniczne nie są polami użytkownika i nie należy dodawać ich do fields. Należą do nich submission_id, form_slug, process_status i current_stage.
